## Test adjustments / STP inconsistencies (not code defects; tests encode the correct behaviour)

* QT-021: the initial speedometer frame is t=0 (speed 88, rpm 4310), not speed 0; needle endpoint is verified with the speed formula from the displayed value (STP allows this).
* QT-036: the Simple Icons strategy is used by 24 chips with 19 distinct slugs (qt x5, stmicroelectronics x2); the STP "19 slugs" is read as distinct slugs.
* QT-037: the ISO strip block icon is `verified_user`; the title icon is `shield` (as in the baseline).
* QT-040: wide cards are titled "SUV In-Vehicle Infotainment System" and "ADAS 3D Demonstrator & R&D Projects"; matched by regex.
* QT-062: at 390 px the nav `.theme-btn` is not hidden (no such rule in baseline CSS, which has to be preserved); the mobile project drives the theme through the menu button and does not assert that the desktop button is hidden.
* QT-064: no element carries `.glass`; the "cards/controls 0.8/0.5/0.4/0.5 s" rule is verified on `.gauge-widget`, `.profile-info-panel`, `footer` (the other selectors in that CSS group are overridden by later `transition: all` rules in baseline and candidate alike); `.theme-btn` has `all 0.3s`.
* QT-071: reveal is verified by scrolling through the page in half-viewport steps (jumping to each section top does not intersect elements in the middle of tall sections).
* QT-076: Contact is the last section; the page bottom prevents its top reaching the nav (label top ~ 160 px), so the check is "label visible below the 54 px nav".
* QT-079: the markup has `.resume-inner` / `.certs-grid` and no `.skills-grid` element (also in the baseline), so the skills 2-column rule cannot be observed; the other grids are checked.
* QT-092 / QT-096: outline-width is read after 350-400 ms because `transition: all` animates it.
* QT-097: markup and baseline contain 10 `target=_blank` links (5 design, 3 social, View Online, preview View); STP's ">= 13" is read as >= 10.
* QT-109/110/111: capture conditions come from `baseline/capture-baseline.mjs` constants. The Simple Icons CDN is aborted (the baseline was captured with it unreachable, so chips show the "code" fallback icon). Comparison is a pure-JS decoder + pixelmatch-style YIQ diff (threshold 0.2, anti-aliased pixels ignored, element ratio 0.001, full page 0.002, up to two re-captures to absorb blur raster jitter). Allowed differences per NFR-MAINT-008 that do not render: skip link (off-screen), aria attributes, `id="main"`, theme-before-paint, unified resume download name; masked/dynamic nodes (typewriter, gauge, particles, orbs) are excluded and the DOM parity check normalises the static t=0 gauge text and the reduced-motion typewriter word. Result: all 13 targets x 2 themes x 2 viewports within tolerance, DOM parity identical.
* QT-015/016/021/089: with a paused/fake clock, lazy sections are only revealed after `page.clock.runFor` (React's 300 ms Suspense throttle uses `setTimeout`), handled in `visual-helpers.js` and the tests.
* Heavy `page.clock.runFor` tests (QT-061/062/063) run under `reducedMotion` so the speedometer rAF loop does not flood the fake clock.
